# Bölüm 3: Fine-Tuning Kırma Testleri ve Adli Bilişim (Red-Teaming) Raporu

Bu çalışma, Hugging Face LLM kursunun **Bölüm 3 (BERT + MRPC ile fine-tuning)** içeriği üzerinde yürütülmüş bir kırma testi (QA ve adli bilişim) analizidir. Doğru çalışan bir fine-tuning hattında kontrollü olarak **tek bir noktayı** bozarak, hatanın **gürültülü çöküş** (kod hata verir) mi yoksa **sessiz bozulma** (kod hatasız çalışır ama sonuç yanlıştır) mı ürettiği belgelenmiştir. Ayrıca eğitilmiş modelin kendisi zor girdilerle sınanmıştır.

---

## 1. Yönetici Özeti ve Deney Tasarımı

Her testte aynı üç adım izlenmiştir:

1. **Kontrol (baseline):** Kod doğru haliyle çalıştırılır ve sonuç kaydedilir.
2. **Deney:** Kodda yalnızca tek bir şey bozulur. Her çalıştırma **aynı seed (42)** ile yapıldığı için fark yalnızca bozulan şeyden gelir.
3. **Karşılaştırma:** Kanıt, hata mesajı (gürültülü çöküş) ya da baseline ile deney arasındaki sayısal fark (sessiz bozulma) olarak belgelenir.

Sessiz bozulma daha tehlikelidir: hata yoktur, ancak sonuç yanlıştır. Adli bilişim açısından asıl vurgu budur.

**Ayarlar (kurs §4 döngüsüyle aynı):** `bert-base-uncased`, GLUE/MRPC (3668 eğitim, 408 doğrulama), eğitim ve doğrulama batch boyutu 8, AdamW (lr $5\times10^{-5}$), doğrusal lr scheduler, 3 epoch (1377 adım), Colab GPU. Etiketler: 1 = `equivalent` (aynı anlam), 0 = `not_equivalent`.

**Referans sayılar:** Doğrulama setinde `equivalent` oranı 0.6838'dir. Yani model hiçbir şey öğrenmeden hep `equivalent` dese accuracy **0.6838**, hep `not_equivalent` dese **0.3162** olur. Sessiz bozulmalar bu referanslarla karşılaştırılarak okunur.

| Test No | Bozulan Şey | Kurs Bölümü | Tür | Beklenen | Gözlenen |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Kontrol** | Yok (doğru ayarlar) | §4 | – | accuracy ≈ 0.84-0.86 | accuracy **0.8554**, son loss 0.0618, `equivalent` oranı 0.706 |
| **1** | `remove_columns` unutuldu | §2, §4 | Gürültülü | Hata verir | **`ValueError`** |
| **2** | `zero_grad()` silindi | §4 | Sessiz | Accuracy düşer, loss yükselir | accuracy 0.8554 → **0.6838**, loss 0.0618 → **0.8083**, `equivalent` oranı **1.0** |
| **3** | Learning rate $5\times10^{-5} \rightarrow 10^{-2}$ | §5 | Sessiz | Model tek cevaba çöker | accuracy **0.6838**, `equivalent` oranı **1.0**, loss 0.6583 |
| **4** | Kelimeleri aynı, anlamı farklı çiftler | §3 modeli | Sessiz | Zor çiftlerde yanılır, kontrollerde doğru bilir | zor çiftler **0/3** doğru, paraphrase kontrolü 1/1, alakasız kontrolü 1/1 |

Tüm beklentiler gerçekleşmiştir. Test 2 ve 3'te model, hata vermeden çalışırken **tek bir sabit cevaba** (hep `equivalent`) çökmüş ve accuracy'si çoğunluk sınıfı tabanına (0.6838) eşitlenmiştir.

## 2. Bütünleşik Test Betiği (Python)

Aşağıdaki kod bloğu notebook'taki hücreleri sırasıyla birleştirir:

```python
# ==============================================================================
# HUGGING FACE LLM COURSE - BÖLÜM 3: FINE-TUNING KIRMA TESTLERİ (4 TEST)
# ==============================================================================

!pip install -q -U datasets accelerate scikit-learn   # Colab hücresi

import torch, numpy as np
from datasets import load_dataset
from transformers import (AutoTokenizer, AutoModelForSequenceClassification,
                          DataCollatorWithPadding, get_scheduler, set_seed)
from torch.utils.data import DataLoader
from torch.optim import AdamW
from sklearn.metrics import accuracy_score, f1_score

QUICK = False     # True: sadece 250 adım (hızlı deneme)
SEED = 42
device = "cuda" if torch.cuda.is_available() else "cpu"
print("Cihaz:", device)

summary = []
def log(test, beklenen, gozlenen):
    summary.append((test, beklenen, str(gozlenen)))

# ------------------------------------------------------------------------------
# HAZIRLIK: VERİ VE EĞİTİM FONKSİYONU (Kurs §2 ve §4)
# ------------------------------------------------------------------------------
checkpoint = "bert-base-uncased"
raw = load_dataset("nyu-mll/glue", "mrpc")
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)

tokenized = raw.map(tokenize_function, batched=True)
collator = DataCollatorWithPadding(tokenizer=tokenizer)

# Doğru hazırlık: gereksiz sütunları at, label -> labels, torch formatı
clean = tokenized.remove_columns(["sentence1", "sentence2", "idx"]).rename_column("label", "labels")
clean.set_format("torch")
train_dl = DataLoader(clean["train"], shuffle=True, batch_size=8, collate_fn=collator)
eval_dl = DataLoader(clean["validation"], batch_size=8, collate_fn=collator)

# Referans sayılar
oran_equiv = float(np.mean(raw["validation"]["label"]))
print(f"Doğrulama setinde 'equivalent' oranı : {oran_equiv:.4f}  -> hep 'equivalent' dersen accuracy bu")
print(f"Doğrulama setinde 'not_equivalent'   : {1 - oran_equiv:.4f}  -> hep 'not_equivalent' dersen accuracy bu")

NUM_EPOCHS = 3
MAX_STEPS = 250 if QUICK else None

def train_loop(lr=5e-5, zero_grad=True):
    set_seed(SEED)
    model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2).to(device)
    optimizer = AdamW(model.parameters(), lr=lr)
    num_steps = NUM_EPOCHS * len(train_dl)
    scheduler = get_scheduler("linear", optimizer=optimizer, num_warmup_steps=0, num_training_steps=num_steps)
    model.train()
    losses, step = [], 0
    for epoch in range(NUM_EPOCHS):
        for batch in train_dl:
            batch = {k: v.to(device) for k, v in batch.items()}
            loss = model(**batch).loss
            loss.backward()
            optimizer.step()
            scheduler.step()
            if zero_grad:                 # <-- Test 2'de zero_grad=False yapıp bunu kapatıyoruz
                optimizer.zero_grad()
            losses.append(loss.item())
            step += 1
            if MAX_STEPS and step >= MAX_STEPS:
                return model, losses
    return model, losses

def evaluate_model(model):
    model.eval()
    preds, refs = [], []
    for batch in eval_dl:
        batch = {k: v.to(device) for k, v in batch.items()}
        with torch.no_grad():
            logits = model(**batch).logits
        preds += logits.argmax(-1).tolist()
        refs += batch["labels"].tolist()
    preds, refs = np.array(preds), np.array(refs)
    return {"accuracy": round(float(accuracy_score(refs, preds)), 4),
            "equiv_orani": round(float(preds.mean()), 3)}   # model örneklerin kaçına 'equivalent' dedi?

def son_loss(losses, n=50):
    return round(float(np.mean(losses[-n:])), 4)

# ------------------------------------------------------------------------------
# KONTROL: DOĞRU AYARLARLA EĞİTİM
# ------------------------------------------------------------------------------
model_ok, loss_ok = train_loop()
res_ok = evaluate_model(model_ok)
print("KONTROL ->", res_ok, "| son loss:", son_loss(loss_ok))
log("Kontrol", "accuracy ≈ 0.84-0.86", f"{res_ok} | loss {son_loss(loss_ok)}")

# ------------------------------------------------------------------------------
# TEST 1: remove_columns UNUTULDU (GÜRÜLTÜLÜ ÇÖKÜŞ)
# ------------------------------------------------------------------------------
bad_dl = DataLoader(tokenized["train"].with_format("torch"), batch_size=8, collate_fn=collator)
try:
    next(iter(bad_dl))
    print("Hata çıkmadı (beklenmedik).")
    log("Test 1: sütun atılmadı", "hata verir", "HATA VERMEDİ")
except Exception as e:
    print("ÇÖKTÜ ->", type(e).__name__)
    print(str(e)[:300])
    log("Test 1: sütun atılmadı", "hata verir", type(e).__name__)

# ------------------------------------------------------------------------------
# TEST 2: zero_grad() SİLİNDİ (SESSİZ BOZULMA)
# ------------------------------------------------------------------------------
model_nz, loss_nz = train_loop(zero_grad=False)
res_nz = evaluate_model(model_nz)
print(f"KONTROL -> {res_ok} | loss {son_loss(loss_ok)}")
print(f"BOZUK   -> {res_nz} | loss {son_loss(loss_nz)}")
print(f"Accuracy farkı: {res_ok['accuracy'] - res_nz['accuracy']:+.4f}")
log("Test 2: zero_grad yok", "accuracy düşer, loss yükselir",
    f"acc {res_ok['accuracy']} -> {res_nz['accuracy']} | loss {son_loss(loss_ok)} -> {son_loss(loss_nz)} | equiv oranı {res_nz['equiv_orani']}")

# ------------------------------------------------------------------------------
# TEST 3: LEARNING RATE ÇOK YÜKSEK, 1e-2 (SESSİZ BOZULMA)
# ------------------------------------------------------------------------------
model_hl, loss_hl = train_loop(lr=1e-2)
res_hl = evaluate_model(model_hl)
print(f"KONTROL (lr=5e-5) -> {res_ok}")
print(f"BOZUK   (lr=1e-2) -> {res_hl} | loss {son_loss(loss_hl)}")
print(f"Referans: hep 'equivalent' = {oran_equiv:.4f} | hep 'not_equivalent' = {1 - oran_equiv:.4f}")
log("Test 3: lr=1e-2", "model tek cevaba çöker",
    f"acc {res_hl['accuracy']} | equiv oranı {res_hl['equiv_orani']} | loss {son_loss(loss_hl)}")

# ------------------------------------------------------------------------------
# TEST 4: KELİMELERİ AYNI, ANLAMI FARKLI ÇİFTLER (MODEL ZAFİYETİ)
# ------------------------------------------------------------------------------
def predict(s1, s2):
    model_ok.eval()
    enc = tokenizer(s1, s2, return_tensors="pt", truncation=True).to(device)
    with torch.no_grad():
        p = model_ok(**enc).logits.softmax(-1)[0]
    return {"not_equivalent": round(p[0].item(), 3), "equivalent": round(p[1].item(), 3)}

# (cümle 1, cümle 2, doğru etiket, grup)
pairs = [
    ("Flights from New York to Florida are cheap.", "Flights from Florida to New York are cheap.", 0, "zor"),
    ("The company raised its prices.", "The company did not raise its prices.", 0, "zor"),
    ("Revenue grew to 5 million dollars.", "Revenue grew to 50 million dollars.", 0, "zor"),
    ("The company raised its prices.", "The firm increased its prices.", 1, "kontrol: gerçek paraphrase"),
    ("The weather is lovely today.", "Stocks fell sharply on Monday.", 0, "kontrol: alakasız"),
]

skor = {}
for a, b, gold, grup in pairs:
    r = predict(a, b)
    tahmin = int(r["equivalent"] > 0.5)
    dogru = tahmin == gold
    g = grup.split(":")[0]
    skor.setdefault(g, [0, 0]); skor[g][0] += int(dogru); skor[g][1] += 1
    print(("DOĞRU  " if dogru else "YANLIŞ "), f"[{grup}]", r)
    print("        ", a, "->", b)

ozet = " | ".join(f"{g}: {d}/{n} doğru" for g, (d, n) in skor.items())
print("\n", ozet)
log("Test 4: kelime sırası/olumsuzlama/sayı", "zor çiftlerde yanılır, kontrollerde doğru bilir", ozet)

# ------------------------------------------------------------------------------
# ÖZET TABLO
# ------------------------------------------------------------------------------
for test, beklenen, gozlenen in summary:
    print(f"{test}\n   Beklenen : {beklenen}\n   Gözlenen : {gozlenen}\n")
```

## 3. Deneyler: Hatayı Nasıl Oluşturduk, Ne Gördük (Adım Adım)

Bu bölüm her testi aynı dört adımda anlatır:

1. **Önce:** Doğru çalışan kod.
2. **Sonra:** Bozduğumuz tek satır (`diff` biçiminde: `-` silinen, `+` eklenen).
3. **Konsol çıktısı:** Colab GPU'da alınan gerçek çıktı (indirme çubukları ve `LOAD REPORT` tabloları sadeleştirilmiştir).
4. **Ne gördük:** Kısa yorum. Ayrıntılı teknik açıklama Bölüm 4'tedir.

---

### 3.0. KONTROL: Doğru Ayarlarla Eğitim

Tüm testler bu sonuçla karşılaştırılır. Önce "hiçbir şey öğrenmeden" ne kadar doğru çıkılabileceğini gösteren **referans sayılar** hesaplanır, ardından model doğru ayarlarla (lr $5\times10^{-5}$, `zero_grad` açık, 3 epoch) eğitilir.

```python
model_ok, loss_ok = train_loop()          # doğru ayarlar
res_ok = evaluate_model(model_ok)
```

```text
Cihaz: cuda
Doğrulama setinde 'equivalent' oranı : 0.6838  -> hep 'equivalent' dersen accuracy bu
Doğrulama setinde 'not_equivalent'   : 0.3162  -> hep 'not_equivalent' dersen accuracy bu

KONTROL -> {'accuracy': 0.8554, 'equiv_orani': 0.706} | son loss: 0.0618
```

**Ne gördük:**

- Model **%85.54** doğrulukla çalışıyor; hep aynı cevabı veren bir modelin alabileceği en iyi sonuç (0.6838) çok altında kalıyor. Yani model gerçekten bir şey öğrenmiş.
- `equiv_orani` 0.706: model örneklerin yaklaşık %70'ine `equivalent` diyor. Gerçek oran 0.6838 olduğu için bu sağlıklı bir dağılım.
- **Referans sayılar** (0.6838 ve 0.3162) sonraki testlerde "model çökmüş mü?" sorusunun ölçüsüdür.

---

### 3.1. Test 1: Gereksiz Sütunları Atmayı Unuttuk (Gürültülü Çöküş)

**Hatayı nasıl oluşturduk:** Eğitim verisini modele vermeden önce `sentence1`, `sentence2` ve `idx` sütunlarını atıyorduk. Bu adımı atladık; metin sütunları veri setinde kaldı.

```diff
-clean = tokenized.remove_columns(["sentence1", "sentence2", "idx"]).rename_column("label", "labels")
-clean.set_format("torch")
-train_dl = DataLoader(clean["train"], shuffle=True, batch_size=8, collate_fn=collator)
+bad_dl = DataLoader(tokenized["train"].with_format("torch"), batch_size=8, collate_fn=collator)
+next(iter(bad_dl))      # ilk batch'i almaya çalış
```

**Konsol çıktısı:**

```text
ÇÖKTÜ -> ValueError
Unable to create tensor, you should probably activate truncation and/or padding with
'padding=True' 'truncation=True' to have batched tensors with the same length. Perhaps
your features (`sentence1` in this case) have excessive nesting (inputs type `list`
where type `int` is expected).
```

**Ne gördük:**

- Kod **eğitime başlamadan çöktü**: gürültülü çöküş, yani fark edilmesi kolay bir hata.
- Model sayı bekler, metni tensöre çeviremez. Hata mesajındaki `sentence1` ifadesi asıl nedeni (kalan metin sütunları) dolaylı olarak gösteriyor.
- **Mesaj yanıltıcı:** Bize `padding=True` / `truncation=True` kullanmamızı öneriyor, oysa sorun padding değil, silinmeyen metin sütunları. Mesajı körü körüne uygulayan biri yanlış yönde debug eder.
- `Trainer` bu temizliği kendisi yaptığı için hata yalnızca **elle yazılan döngüde** yaşanır.

---

### 3.2. Test 2: `zero_grad()` Satırını Sildik (Sessiz Bozulma)

**Hatayı nasıl oluşturduk:** Her adımdan sonra gradyanları sıfırlayan `optimizer.zero_grad()` çağrısını kapattık. PyTorch gradyanları varsayılan olarak biriktirdiği için her adımda önceki adımların gradyanı üzerine eklenir.

```diff
 loss.backward()
 optimizer.step()
 scheduler.step()
-optimizer.zero_grad()
```

Fonksiyon çağrısı: `train_loop()` → `train_loop(zero_grad=False)`. Başka hiçbir şey değişmedi (seed, veri, lr aynı).

**Konsol çıktısı:**

```text
KONTROL -> {'accuracy': 0.8554, 'equiv_orani': 0.706} | loss 0.0618
BOZUK   -> {'accuracy': 0.6838, 'equiv_orani': 1.0} | loss 0.8083
Accuracy farkı: +0.1716
```

**Önce / sonra:**

| Ölçü | Kontrol | `zero_grad` yok |
| :--- | :---: | :---: |
| Accuracy | 0.8554 | **0.6838** |
| Son loss (50 adım) | 0.0618 | **0.8083** |
| `equivalent` deme oranı | 0.706 | **1.0** |

**Ne gördük:**

- **Hata mesajı yok**, kod sorunsuz bitti. Eğitim "başarılı" görünüyor; sorun yalnızca sonuçta ortaya çıkıyor: sessiz bozulma.
- Accuracy **tam olarak 0.6838**, yani "hep `equivalent` de" referansı. `equivalent` oranı 1.0 olduğu için bunun nedeni açık: model **her örneğe aynı cevabı** veriyor, hiçbir şey öğrenmemiş.
- Loss 0.8083, bilgisiz tahminin kaybı olan $\ln 2 \approx 0.693$'ün de **üstünde**: model "bilmiyorum" diyen bir tahminciden bile kötü.
- Başta "AdamW bu hataya dayanıklı olabilir" diye tahmin etmiştik. **Tahmin tutmadı:** bu kurulumda dayanıklılık yok.

---

### 3.3. Test 3: Learning Rate'i 200 Kat Büyüttük (Sessiz Bozulma)

**Hatayı nasıl oluşturduk:** Optimizer'ın adım büyüklüğünü belirleyen learning rate'i $5\times10^{-5}$ yerine $10^{-2}$ yaptık. Adımlar o kadar büyük ki model öğrendiği şeyi sürekli bozuyor.

```diff
-optimizer = AdamW(model.parameters(), lr=5e-5)
+optimizer = AdamW(model.parameters(), lr=1e-2)
```

Fonksiyon çağrısı: `train_loop()` → `train_loop(lr=1e-2)`. Başka hiçbir şey değişmedi.

**Konsol çıktısı:**

```text
KONTROL (lr=5e-5) -> {'accuracy': 0.8554, 'equiv_orani': 0.706}
BOZUK   (lr=1e-2) -> {'accuracy': 0.6838, 'equiv_orani': 1.0} | loss 0.6583
Referans: hep 'equivalent' = 0.6838 | hep 'not_equivalent' = 0.3162
```

**Önce / sonra:**

| Ölçü | Kontrol (lr 5e-5) | Bozuk (lr 1e-2) |
| :--- | :---: | :---: |
| Accuracy | 0.8554 | **0.6838** |
| `equivalent` deme oranı | 0.706 | **1.0** |
| Son loss (50 adım) | 0.0618 | 0.6583 |

**Ne gördük:**

- Yine **hata yok**, yine sessiz bozulma. Eğitim tamamlanıyor, ama model her örneğe `equivalent` diyor ve accuracy referans değere (**0.6838**) eşitleniyor.
- Loss (0.6583), girdiden bağımsız sabit bir tahminin kaybına yakın: model **girdiye bakmıyor**, sadece sınıf sıklığını söylüyor.
- **İlginç gözlem:** Bu testin önceki sürümünde (farklı ayarlarla: batch 16, scheduler yok, 250 adım) model **ters sınıfa** çökmüştü (accuracy 0.3162, hep `not_equivalent`). Yani model çöküyor ama **hangi cevaba çöktüğü önceden bilinemiyor**. (İki çalıştırmanın ayarları farklı olduğu için bu bir gözlemdir, nedensel kanıt değildir.)
- Bu yüzden accuracy her zaman **iki referans sayıyla** (0.6838 ve 0.3162) karşılaştırılmalıdır.

---

### 3.4. Test 4: Kelimeleri Aynı, Anlamı Farklı Cümleler (Model Zafiyeti)

**Burada kodu bozmuyoruz; modele zor girdi veriyoruz.** Eğitimi doğru yapılmış kontrol modeline, kelimeleri neredeyse aynı ama anlamı farklı üç çift veriyoruz (yön değişimi, olumsuzlama, sayı değişimi). Doğru cevap hepsinde `not_equivalent`.

Modelin "her şeye `equivalent` diyen" bir model olup olmadığını ayırt etmek için iki **kontrol çifti** ekledik: gerçek bir paraphrase (doğru cevap `equivalent`) ve alakasız bir çift (doğru cevap `not_equivalent`).

```python
def predict(s1, s2):
    model_ok.eval()
    enc = tokenizer(s1, s2, return_tensors="pt", truncation=True).to(device)
    with torch.no_grad():
        p = model_ok(**enc).logits.softmax(-1)[0]
    return {"not_equivalent": round(p[0].item(), 3), "equivalent": round(p[1].item(), 3)}
```

**Konsol çıktısı:**

```text
YANLIŞ  [zor] {'not_equivalent': 0.003, 'equivalent': 0.997}
         Flights from New York to Florida are cheap. -> Flights from Florida to New York are cheap.
YANLIŞ  [zor] {'not_equivalent': 0.003, 'equivalent': 0.997}
         The company raised its prices. -> The company did not raise its prices.
YANLIŞ  [zor] {'not_equivalent': 0.075, 'equivalent': 0.925}
         Revenue grew to 5 million dollars. -> Revenue grew to 50 million dollars.
DOĞRU   [kontrol: gerçek paraphrase] {'not_equivalent': 0.003, 'equivalent': 0.997}
         The company raised its prices. -> The firm increased its prices.
DOĞRU   [kontrol: alakasız] {'not_equivalent': 0.992, 'equivalent': 0.008}
         The weather is lovely today. -> Stocks fell sharply on Monday.

 zor: 0/3 doğru | kontrol: 2/2 doğru
```

**Çiftlere göre sonuç:**

| Çift | Neyi zorluyor? | Doğru cevap | $P(\text{equivalent})$ | Sonuç |
| :--- | :--- | :---: | :---: | :---: |
| New York → Florida / Florida → New York | Kelime sırası (yön) | not_equivalent | 0.997 | Yanlış |
| raised / did **not** raise | Olumsuzlama | not_equivalent | 0.997 | Yanlış |
| 5 million / 50 million | Sayı değeri | not_equivalent | 0.925 | Yanlış |
| raised / firm increased | Kontrol: paraphrase | equivalent | 0.997 | Doğru |
| weather lovely / Stocks fell | Kontrol: alakasız | not_equivalent | 0.008 | Doğru |

**Ne gördük:**

- Model üç zor çiftin **hepsinde yanıldı** ve %92-99 gibi çok yüksek güvenle yanıldı.
- Kontrollerde doğru bildi; yani model "her şeye `equivalent` diyen" bir model **değil**. Alakasız çifte doğru olarak `not_equivalent` dedi.
- Sonuç, modelin **anlama değil kelime örtüşmesine** baktığı hipotezini destekliyor: kelimeleri aynı olan çiftlere `equivalent`, ortak kelimesi olmayan çifte `not_equivalent` dedi.
- **Dikkat:** Bu hipotez kanıtlanmış değil, desteklenmiştir. Paraphrase kontrolünde de kelimelerin çoğu ortak olduğu için bu kontrol "anlıyor mu, örtüşmeye mi bakıyor" sorusunu ayıramıyor. Ayrıca örneklem yalnızca 5 çifttir.

### 3.5. Tüm Testlerin Özeti

```text
Kontrol                    accuracy 0.8554 | equiv oranı 0.706 | loss 0.0618
Test 1: sütun atılmadı     ValueError (eğitim başlamadan çöktü)
Test 2: zero_grad yok      accuracy 0.6838 | equiv oranı 1.0   | loss 0.8083
Test 3: lr=1e-2            accuracy 0.6838 | equiv oranı 1.0   | loss 0.6583
Test 4: zor çiftler        0/3 doğru (kontroller 2/2 doğru)
```

**Ortak sonuç:** Test 1 hata verdiği için fark edildi. Test 2 ve 3 **hata vermedi** ve model tek bir sabit cevaba çöktü; bunları yalnızca sonuçları referans sayılarla (0.6838 / 0.3162) karşılaştırarak yakaladık. Test 4 ise iyi görünen bir modelin (accuracy %85) bile zor girdilerde nasıl yanıldığını gösterdi.

## 4. Teknik ve Mimari Değerlendirme

### 4.1. Test 1: Eksik Sütun Temizliği (Gürültülü Çöküş)

`tokenize_function` yalnızca `input_ids`, `token_type_ids` ve `attention_mask` ekler; `sentence1`, `sentence2` ve `idx` sütunları veri setinde kalır. `DataCollatorWithPadding` yalnızca sayısal alanları pad'leyip tensöre çevirebilir; string sütunlarla karşılaşınca hata verir. Kurs metni de bu sütunların "string içerdiği için tensör yapılamayacağını" ve `Trainer`'ın bu adımı kendisi yaptığını söyler.

Gözlem: **`ValueError`**. Bu, **iyi bir çöküştür**: hata erken, açık ve eğitimden önce ortaya çıkar. Ancak hata mesajı yanıltıcıdır: kullanıcıyı `padding=True` / `truncation=True` kullanmaya yönlendirir, oysa asıl neden veri setinde kalan string sütunlardır (mesaj bunu yalnızca "`sentence1` ... excessive nesting" ifadesiyle dolaylı olarak belirtir). Yani bu tür çöküşler de yanlış yönde debug edilebilir.

### 4.2. Test 2: `zero_grad()` Silinmesi (Sessiz Bozulma)

PyTorch gradyanları varsayılan olarak **biriktirir**. `optimizer.zero_grad()` çağrılmadığında $t$. adımda optimizer'a verilen gradyan, o adımın değil geçmiş tüm adımların toplamıdır:

$$
g_t^{\text{biriken}} = \sum_{k=1}^{t} \nabla_\theta \mathcal{L}_k(\theta_k)
$$

Gözlem: kod **hata vermeden** çalıştı; accuracy 0.8554'ten **0.6838**'e, son 50 adım ortalama loss ise 0.0618'den **0.8083**'e geçti. Modelin `equivalent` deme oranı **1.0**'dır: model doğrulama setindeki **her** örneğe `equivalent` demektedir.

Bu üç sayı birlikte okunmalıdır:

- **0.6838**, doğrulama setindeki `equivalent` oranıyla (çoğunluk sınıfı tabanı) birebir aynıdır. `equivalent` oranının 1.0 olması bunu doğrudan açıklar: model fiilen hiçbir şey öğrenmemiş, sabit bir cevap veriyordur.
- **0.8083 loss**, iki sınıflı problemde bilgisiz (rastgele) tahminin kaybı olan $\ln 2 \approx 0.693$'ün **üzerindedir**. Yani model, hiçbir şey bilmeyen bir tahminciden bile kötü kayıp üretmektedir; bu, yanlış örneklerde kendinden emin tahminler yapıldığına işaret eder. (Bu değer son 50 eğitim batch'inin, yani 400 örneğin ortalamasıdır; gürültülü bir ölçümdür.)
- Accuracy düşüşünün tek başına ($-0.1716$) yeterince alarm vermesine rağmen, **hata mesajı olmaması** bu bozulmayı tehlikeli kılar.

Notebook'un ilk sürümünde "AdamW gradyanı normalize ettiği için etki hafif olabilir" varsayımı yapılmıştı. Gözlem bunun tersini gösterdi: **AdamW bu hataya dayanıklı değildir**, en azından bu kurulumda. Olası mekanizma, eski gradyanların yeni batch'in sinyalini bastırması ve güncelleme yönünün mevcut veriden kopmasıdır (bu mekanizma ayrıca ölçülmemiştir).

### 4.3. Test 3: Aşırı Yüksek Learning Rate (Sessiz Bozulma)

Learning rate $5\times10^{-5}$ yerine $10^{-2}$ (200 kat) yapıldığında accuracy **0.6838** oldu ve `equivalent` oranı **1.0**'dır; kod yine hata vermedi. Model her örneğe `equivalent` demektedir, yani çoğunluk sınıfına çökmüştür.

Loss değeri 0.6583'tür. Doğrulama setindeki sınıf oranıyla (0.6838) sabit bir tahmin yapan bir modelin kaybı yaklaşık 0.62-0.63 civarındadır; gözlenen değer bu düzeye yakındır. Bu da modelin girdiden bağımsız, yalnızca sınıf sıklığını yansıtan bir çıktı ürettiği yorumuyla uyumludur.

**Önemli bir gözlem:** Bu testin önceki sürümünde (farklı ayarlarla: batch 16, lr scheduler yok, 250 adım) aynı hata **tam tersi sınıfa** çökmüştü (accuracy 0.3162, yani hep `not_equivalent`). Aynı bozulma, eğitim ayarları değişince farklı bir sabit cevaba yol açmıştır. Çıkarım: yüksek learning rate'te model çöker, ancak **hangi sınıfa çöktüğü önceden tahmin edilemez**. Bu yüzden accuracy, tek bir tabanla değil **her iki sabit sınıf tabanıyla** (0.6838 ve 0.3162) karşılaştırılmalıdır. (İki çalıştırmanın ayarları farklı olduğu için bu karşılaştırma nedensel bir iddia değil, bir gözlemdir.)

### 4.4. Test 4: Kelime Sırası, Olumsuzlama, Sayı (Model Zafiyeti)

Doğru cevabı `not_equivalent` olan üç "zor" çift verildi: yön değişimi (New York → Florida / Florida → New York), olumsuzlama (raised / did not raise) ve sayı değişimi (5 million / 50 million). Bunların yanında iki **kontrol çifti** kullanıldı: gerçek bir paraphrase (doğru cevap `equivalent`) ve alakasız bir çift (doğru cevap `not_equivalent`).

| Çift | Doğru Cevap | $P(\text{equivalent})$ | Sonuç |
| :--- | :---: | :---: | :---: |
| New York → Florida / Florida → New York | not_equivalent | 0.997 | Yanlış |
| raised / did not raise | not_equivalent | 0.997 | Yanlış |
| 5 million / 50 million | not_equivalent | 0.925 | Yanlış |
| raised / The firm increased (paraphrase kontrolü) | equivalent | 0.997 | Doğru |
| weather lovely / Stocks fell (alakasız kontrolü) | not_equivalent | 0.008 | Doğru |

Zor çiftlerin **hepsinde** model yanılmış ve `equivalent` için 0.925 ile 0.997 arasında olasılık vermiştir. Kontrol çiftlerinde ise doğru cevap vermiştir. Bu, modelin "her şeye `equivalent` diyen" bir model olmadığını gösterir (alakasız çifte `not_equivalent` demiştir). Sonuç, modelin **anlamsal eşdeğerlik yerine yüzeysel kelime örtüşmesine** dayandığı hipotezini destekler: kelimeleri neredeyse aynı olan çiftlere `equivalent`, hiç ortak kelimesi olmayan çifte `not_equivalent` demiştir.

Bu hipotez **kanıtlanmış değil, desteklenmiştir**; dikkat edilmesi gereken sınırlar:

- Paraphrase kontrolü de yüksek kelime örtüşmesine sahiptir (ilk cümlenin büyük kısmı tekrar eder). Bu nedenle bu kontrol, modelin "anlamı anlayarak" mı yoksa "örtüşmeye bakarak" mı `equivalent` dediğini **ayıramaz**. Ayırmak için, örtüşmesi düşük ama anlamı aynı bir paraphrase çifti de gerekir.
- Örneklem yalnızca 5 çifttir; istatistiksel genelleme yapılamaz.
- Yanlışların nedeni bu testle izole edilmemiştir.

Dikkat çekici olan, hataların **çok yüksek güvenle** yapılmasıdır. Softmax çıktısı modelin "emin" olduğunu söyler; ancak bu güven doğruluğun göstergesi değildir (kalibrasyon sorunu).

### 4.5. Deneyin Sınırları

- **Tek seed, tek çalıştırma:** Sonuçlar GPU ve çalıştırmaya göre değişebilir; farkların varyansı ölçülmemiştir.
- **Küçük doğrulama seti:** 408 örnekte tek bir örnek yaklaşık %0.245 accuracy'ye denk gelir.
- **Küçük örneklem:** Test 4 yalnızca 5 çift içerir; sonuçlar gösterim amaçlıdır, istatistiksel iddia değildir.
- **Loss, eğitim kaybıdır:** Raporlanan "son loss" değerleri son 50 eğitim batch'inin ortalamasıdır, doğrulama kaybı değildir. Kontrolün düşük değeri (0.0618) ile 0.8554 doğrulama accuracy'si arasındaki fark, modelin eğitim verisine yüksek uyum sağladığına işaret eder.
- **Kurs ile uyum:** Eğitim döngüsü kurs §4'teki ayarlarla (batch 8, doğrusal scheduler, 3 epoch) kurulmuştur. Kursun kendi metninde kontrol sırasında fark edilen şu tutarsızlıklar vardır: (1) §3'te "`cased` model kullanıyoruz" yazar ama kodda `bert-base-uncased` vardır; (2) §5'te "learning rate'i düşürün" yazar ama kod farkı lr'yi 1e-5'ten 1e-4'e **artırır**; (3) §5'te early stopping `patience=3` "3 ardışık epoch" diye anlatılır, oysa örnekte `eval_steps=100` kullanıldığı için sayaç epoch değil değerlendirme sayısıdır.

## 5. Savunma Notları ve Öneriler

* **Eğitim Hattı Doğrulaması:** Elle yazılan döngüler yerine mümkünse `Trainer` kullanılmalıdır; `Trainer`, Test 1 ve Test 2'deki hata sınıflarını yapısal olarak engeller. Elle döngü zorunluysa ilk batch sonrası şekil/tip kontrolü (`assert`) eklenmelidir.
* **Sessiz Bozulmaya Karşı İzleme:** Eğitim sonunda accuracy, **her iki sabit sınıf tabanıyla** (hep 0, hep 1) ve loss ise $\ln K$ ($K$ sınıf sayısı) ile karşılaştırılmalıdır. Bu çalışmada Test 2 ve 3'te model tam olarak çoğunluk tabanına (0.6838) yapışmıştır ve `equivalent` oranı 1.0 olmuştur; bu tür bir kural ya da "tahmin dağılımı tek sınıfta mı" kontrolü otomatik alarm üretebilir.
* **Hiperparametre Taraması:** Learning rate'i keşfetmek için kısa bir "LR range test" yapılmalı, eğitim sırasında loss ve gradyan normu loglanmalıdır.
* **Adversarial Değerlendirme:** Standart doğrulama accuracy'si (0.8554) Test 4'teki zafiyeti göstermez. Kelime sırası ve olumsuzlama için **PAWS** gibi adversarial paraphrase veri setleriyle ek değerlendirme yapılmalı, gerekirse eğitim verisi bu tür örneklerle zenginleştirilmelidir.
* **Kalibrasyon:** Softmax skoru ham güven olarak sunulmamalı; sıcaklık ölçekleme (temperature scaling) gibi kalibrasyon yöntemleri uygulanmalıdır.
